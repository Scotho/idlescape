# SDD ledger for plan docs/superpowers/plans/2026-09-05-spw-wiki-corpus.md

Spec: docs/superpowers/specs/2026-09-05-spw-wiki-corpus-design.md (approved 2026-09-05, "agreed").
Merged to `develop` 2026-09-05 as a fast-forward to `59be76f` (78 commits, including the SP1/SP1b
work it was built on). Owner approved "for this phase, addl polish can be added later".

SPW built a wiki of the game at `/wiki` (reader) and `/api/wiki` (agent query API), extracted
from the pinned Content/Engine clones into a build-time SQLite corpus (`wiki/build/wiki.db`,
entity tables plus FTS5), with a source on every fact and a lint enforcing an OSRS-Wiki-style
voice. Sixteen tasks, each with a fresh implementer and reviewer, fix rounds until clean, then a
final review and one fix wave.

Work happened in an isolated worktree (`C:\Projects\osrs_test\.claude\worktrees\wiki-corpus`,
branch `feat/wiki-corpus`, `engine/` a directory junction to the real clone) because another
session held uncommitted edits on `feat/platform-shell` in the main checkout. That worktree, and
its own `.superpowers/` ledger, no longer exist; this document is that ledger promoted out of
machine-local memory (`spw-wiki-corpus-ledger.md`, `spw-wiki-corpus-status.md`) per audit finding
C13/decision D19.

Baseline before work started: server `bun test` 51 pass / 3 fail (bridge.test, pair/routes.test,
pair/store.test need the Firestore emulator; unrelated to this plan). web vitest 19/19.
Harness note from the worktree: nested shells (bash/cmd/awk programs) were refused inside it;
briefs were cut with `sed` line ranges; review packages used plain `git log`/`diff` redirects.

## Rulings

Preflight, scope-setting:

- Work in the isolated worktree rather than in place, to avoid colliding with the other
  session's uncommitted edits on `feat/platform-shell`, cost if wrong: a merge back at the end.
- Sprites (spec 8.1 `/wiki/sprites/*`) stay out of this plan per the plan's Global Constraints;
  the reader renders without images, cost if wrong: a follow-up plan (this held).
- `parseWeight` uses 453 g/lb and 28.35 g/oz so the Task 2 tests hold, cost if wrong: weights
  off by under 1 g.
- `WikiDb.search` (Task 13) retries the FTS query with OR between tokens when the AND form
  returns nothing, so the reader's "did you mean" finds near-misses, cost if wrong: broader
  search results on multi-word misses.
- Source markers in assembled pages are plain ` [1]`-style bracketed numbers, not `[^1]`
  footnote syntax (`marked` has no extension for it and would render it literally), cosmetic.

## Traps hit

- **Category death scripts → phantom NPC keys.** `drops.ts` was attributing category-subject
  death scripts (`[ai_queue3,_barbarian]`-style, leading underscore means a category) to a
  phantom NPC key like `_barbarian` instead of expanding to every NPC whose config has
  `category=<name>`. 37 such scripts in the 274 content produced 469 drop rows across 15 phantom
  keys. Fixed in the final wave by threading `NpcEntity.category` from the `.npc` config plus
  category-id names from `pack/category.pack` into `extractDrops`, then re-extracting.
- **Strict-mode Playwright locator.** `locator('article h2', { hasText: 'Sources' })` matched
  both "Item sources (derived)" and "Sources" on item pages; fixed to
  `getByRole('heading', { name: 'Sources', exact: true })`.
- **Mid-plan rev bump.** A concurrent session's `scripts/upstream.lock` bump to content rev 274
  forced a rebase and a same-task pivot (Task 9 ruling above), a reminder that pinned-revision
  plans running in parallel with upstream-bump plans need to check the lock file, not assume it
  is stable for the plan's duration.
- **Worktree/env drift.** `web/.env.local` (git-ignored Firebase config) had to be copied from
  the main checkout into the worktree for `connect.test.ts`/`connectCard.test.ts` to load. The
  entry-screen redesign landed in the main checkout mid-plan and renamed `signin.html` to
  `entry.html`, invalidating Task 14's brief references (ruling above).
- **API session limit.** Task 15's first dispatch died on an API session limit with no files or
  commits written; a plain redispatch after the limit reset picked it up cleanly, no special
  recovery needed.
- **Ledger location.** The SDD ledger lived under the worktree's `.superpowers/`, which is
  deleted with the worktree; it survived only because it was hand-copied to machine-local memory
  at close, which is itself a durability trap (audit C13), this document is the fix.
